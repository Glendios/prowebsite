AI developer tooling

Agent Memory MCP Server

I use Claude Code and Codex side by side every day. Each one forgets everything between sessions and can't see what the other did. This server gives both agents one shared memory and a searchable record of every conversation either of them has had.

Python (standard library only) Model Context Protocol SQLite FTS5 JSON-RPC over stdio

Result

128K+ messages, about 2 ms per search

Every user and assistant message from both tools goes into one full-text index. Either agent can search it, list a project's past sessions, read a session page by page, or pick up the other agent's latest session where it stopped.

  • 12 tools: memory search, list, read and write; chat search; project sessions; session read; latest session; index status; and import of a session into the other agent.
  • A Codex conversation can be turned into a Claude Code session, and the reverse, with its messages and tool output intact.
  • No date window: the index covers every session on the machine, not just recent ones.

Design choices

Full-text search over embeddings. Most lookups are for exact things: an error message, a file name, a decision. FTS5 finds those in milliseconds with no model calls and no extra service to run.

Standard library only. The server is one Python process started by each agent. Nothing to install means it starts the same way on any machine with Python.

Incremental indexing. A background thread reads only what changed in each session file since the last pass, so the index stays current without re-reading gigabytes of logs.

Safeguards

It reads only the two agents' session folders and the memory files, never credentials. Very large lines and messages are capped so one oversized log can't stall indexing. Writes go only to the shared memory folder.

Ownership

I designed the schema, the incremental indexing approach, the MCP tool interfaces and the test plan. I used Claude Code and Codex as implementation assistants, then inspected, tested and revised what they produced. The hardest part was indexing live logs safely: session files grow while agents write to them, so the indexer tracks how far it has read in each file and only commits complete lines.
