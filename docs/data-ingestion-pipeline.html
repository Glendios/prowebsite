Data pipeline

Multi-Source Data Ingestion Pipeline

Job postings live in dozens of places that each describe the same job differently: company career sites, applicant-tracking systems, aggregators and government boards. This pipeline pulls them into one store, recognizes the same posting across sources, and ranks what's new.

Python REST APIs Playwright Concurrency pytest

Scale

43K+ records from 32 source types

Each source has its own adapter that turns its format into one common record. Where a source has a public API (Greenhouse, Lever, Ashby, Workday and others) the adapter calls it directly; browser automation is used only for sites without one.

  • An hourly watcher checks 2,000+ company job boards in about 70 seconds. It reads each applicant-tracking system's public job-board API, the same feed those companies publish for job sites, through a small bounded thread pool, and keeps only postings published since the last pass.
  • 700+ automated tests cover the adapters, deduplication, ranking and the error paths.
  • New matches above a fit threshold are sent as one daily digest, each posting at most once.

Deduplication

Every record gets a stable ID built from the system that actually hosts the posting and that system's own posting ID. The same job found through an aggregator, a search site and the company's own board resolves to one record, and re-running any adapter updates records instead of creating new ones.

Ranking

Hard filters drop postings that fail on location, level or posted pay. The rest are scored on fit, freshness, pay and career value, and the scores were checked against independent ratings of the same postings before the weights were set.

Failure handling

Sources break constantly: rate limits, layout changes, expired listings. Each adapter fails on its own without stopping the run, a shared lock keeps two runs from writing at once, and closed postings are recorded so they stop coming back.

Being a good client

API sources are preferred over page scraping. Browser automation is paced and runs one page at a time, a source that fails is skipped until the next run instead of being retried in a loop, and any change to a scraper is tested against a single live page before a full run.
