Multi-Source Data Ingestion Pipeline

Python, REST APIs, Playwright, pytest

I built this for my own job search. The same posting shows up on company sites, applicant-tracking systems, aggregators and government boards, each with different fields. The pipeline collects them from 32 source types into one store of 43K+ records and keeps one record per real posting.

Sources

Each source has an adapter that converts it to the same record schema. Greenhouse, Lever, Ashby, Workday and other applicant-tracking systems publish job-board APIs, and the adapters use those. Browser automation is only for sites that have no API.

An hourly job checks 2,000+ company boards through those APIs in about 70 seconds, using a small bounded thread pool, and keeps postings published since the last run.

Deduplication

A record's ID combines the system that hosts the posting with that system's own posting ID. A copy found through LinkedIn or an aggregator resolves to the same record, and running an adapter again updates the record in place.

Ranking

Postings that fail on location, level or posted pay are dropped. The rest are scored on fit, freshness, pay and career value. Before setting the weights, I compared the scores with separate blind ratings of the same postings. Matches above the threshold go out in one daily email, and a posting is never sent twice.

When sources break

Rate limits, layout changes and removed listings are routine. A failing adapter is logged and skipped until the next run, and the rest of the run continues. A file lock stops two runs from writing at once, and closed postings are recorded so they don't come back.

Browser automation goes one page at a time at a slow pace. Before a scraper change runs against a whole site, I test it on one live page. I added that rule after a change triggered a rate limit.

There are 700+ pytest tests, mostly for the adapters, deduplication and the error paths.
