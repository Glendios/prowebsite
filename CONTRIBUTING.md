# Contributing

Canonical guide for phantom.moe (this repo). `AGENTS.md` and `CLAUDE.md` point here; do not copy these rules into new root docs. Hosting state, open items and history live in `NOTES.md`.

## How the site is built

- Plain static HTML/CSS/JS in `docs/`. No build step, no framework.
- GitHub Pages publishes `docs/` from `main` to `phantom.moe` (`docs/CNAME`). Pushing to `main` publishes.
- **Everything under `docs/` is public.** Notes, logs, plans, local paths and agent output never go there. Private notes go in `NOTES.md` at the repo root.
- Subdomain apps live in their own repos: tasks/lol/osrs on Vercel, wynn on Cloudflare Pages. See `NOTES.md`.
- `src/` is an old pre-`docs/` copy of the site and is gitignored. Do not edit it.

## Where things go

| Change | Where |
| --- | --- |
| New project page | `docs/<name>.html`, using the existing navbar/footer and `cndictstyle.css` |
| Shared styling | `docs/cndictstyle.css`; bump the `?v=YYYYMMDD` cache key on every page that links it |
| Dictionary tool behavior | `docs/cndictscript.js`; bump its `?v=` key in `cndict.html` |
| New route or subdomain | Add a row to `docs/directory.html` and update its summary counts |
| Wynncraft pages (`docs/wynncraft-addons/`, `docs/wynncraft-market/`) | Generated by the publishers in `Documents/ChatGPT/wymn`. Do not hand-edit |
| Private working notes, findings, decisions | `NOTES.md` |

## Public copy rules

- Pages describe what a tool does, how it works, and what a visitor can inspect.
- No recruiter, role-fit, or portfolio-strategy wording. No "what this demonstrates", "worth highlighting", or deployment-safety notes. No disclaimers that justify unfinished work.
- Keep the full name off public metadata. The public identity is "Phantom Tools"; the contact path is github.com/Glendios.
- Private entry points (`docs/a/`, the directory) use vague wording that doesn't say what they lead to.

## Formatting

Edit HTML by hand in the existing style of the file. Do not run a formatter over whole files: `.prettierignore` excludes `docs/` because a whole-file reformat once left three pages with a large diff and no real change.

## Verify

```bash
npm run verify
```

`scripts/verify.mjs` has no dependencies. It checks:

- the agent docs exist, there are no duplicate root policy docs, and no scratch files are tracked;
- `docs/` has no `.md` files and no local Windows paths;
- every page has a `<title>`, and project pages have exactly one `<h1>`;
- every relative `href`/`src` resolves;
- source files stay under the line budget;
- a local server returns 200 for every page.

The pre-commit hook (`.githooks/pre-commit`, enabled with `git config core.hooksPath .githooks`) and CI (`.github/workflows/ci.yml`) run the same command. Do not bypass the hook with `--no-verify`.

## Anti-patterns

- Adding `ARCHITECTURE.md`, `SESSION_START.md`, `*_MEMORY.md` or similar root docs. Update this file or `NOTES.md` instead.
- Committing a formatting-only rewrite mixed with real changes.
- Linking `directory.html` or `docs/a/` from public navigation.
